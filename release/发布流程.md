# VideoEnhancer 发布流程

本文是独立维护版的发布前门禁和操作指导。发布分为两条相互独立但需要交叉核对的链路：

- **本体发布**：GitHub Release 为首选版本检查与更新包来源，ModelScope `VideoEnhancer-Releases` 为检查和下载兜底。
- **模型资源发布**：ModelScope `VideoEnhancer-Models` 为模型资源仓库。模型不打包进本体 ZIP，也不上传到 GitHub Release。

发布完成前，不能只验证其中一条链路。任何一条链路失败，都不要对外宣布“已发布”。

## 1. 发布约定

### 1.1 版本号

- 使用独立 SemVer：`X.Y.Z`，不跟随上游版本号。
- 当前版本唯一源：
  - `VideoEnhancerPlugin/PluginVersion.vb` 的 `PluginVersion.Current`。
  - `cli/VideoEnhancer.csproj` 的 `<Version>`。
- 两处必须完全一致。发布脚本会再次读取并校验，禁止只修改其中一处。
- 已经发布过的版本不得重写或覆盖。发现问题时递增版本发布修正版，例如 `1.0.5` → `1.0.6`。
- `UpstreamBase` 只记录同步基线，不参与更新比较。

### 1.2 仓库职责

| 内容 | GitHub | ModelScope |
| --- | --- | --- |
| `videoenhancer.exe`、插件 DLL、布局 JSON | Release ZIP 中发布 | `VideoEnhancer-Releases` 镜像发布 |
| `stable.json` | Release 资产，版本检查首选 | 同内容镜像，GitHub 失败时兜底 |
| 超分/补帧/后端模型 | 不发布 | `VideoEnhancer-Models` |
| `PotPlayer.7z` | 不发布 | 不发布 |

### 1.3 本体更新包内容

本体 ZIP 只允许包含以下四项：

```text
videoenhancer.exe
videoenhancer.3fui.dll
videoenhancer-layout.json
package.json
```

更新器实际替换前三个运行文件，替换前备份，失败自动回滚。不要把模型、Python 环境、FFmpeg、PotPlayer 或其他安装器文件放进本体 ZIP。

## 2. 发布前门禁

以下项目全部通过后才允许上传。不能用“本地能启动”替代哈希、清单或双源检查。

### 2.1 版本和 Git 状态

- [ ] 已确认本次发布版本和变更范围，版本号未复用历史版本。
- [ ] `PluginVersion.vb` 与 `VideoEnhancer.csproj` 版本一致。
- [ ] `git pull` 已尝试；若因本地改动失败，已确认没有误合并或覆盖风险。
- [ ] `git status` 中只有本次预期修改；没有把临时 ZIP、令牌、模型缓存或用户配置加入提交。
- [ ] 版本记录、工作进度和 `docs/codex/STATUS.md` 已准备更新。

### 2.2 依赖和凭据

在 PowerShell 中确认：

```powershell
dotnet --version
gh auth status
modelscope whoami
```

还必须确认：

- [ ] `VideoEnhancerPlugin/build.ps1` 所需的 3FUI 宿主程序集路径存在。
- [ ] GitHub CLI 已登录到有权发布 `maxzrb/VideoEnhancer` 的账号。
- [ ] ModelScope CLI 已登录到有权写入目标数据集的账号。
- [ ] 令牌只存在于登录工具或环境变量，不写入仓库、README、清单或日志。
- [ ] 发布机器有足够磁盘空间；Python 大包、FlashVSR 和模型上传可能占用数 GB 临时空间。

### 2.3 代码、模型和授权门禁

- [ ] 本次功能已完成对应的 CLI、插件和 Python 静态检查。
- [ ] 模型来源、文件名、SHA-256 和再分发状态已有记录。
- [ ] `PotPlayer.7z` 明确排除，任何批量同步命令都没有把它带入上传目录。
- [ ] 未确认授权的模型不得伪装成项目自有内容；至少在发布记录中标注“已确认”或“风险接受”。
- [ ] 不发布不属于本项目目标的上游测试包、旧兼容包或重复归档。

## 3. 构建和本地验收

### 3.1 运行单元和静态检查

在仓库根目录执行：

```powershell
dotnet build cli\VideoEnhancer.csproj -c Release --no-restore
& .\VideoEnhancerPlugin\build.ps1 `
  -HostBin 'C:\path\to\FFmpegFreeUI.6.1.39.extracted' `
  -SkipInstall
python -m unittest cli.tests.test_rve_ordered_backend -v
git diff --check
```

如果本次修改了 Python 工具，再执行：

```powershell
python -m py_compile `
  cli\embedded-tools\convert_tensorrt.py `
  cli\embedded-tools\InterpolateRIFE.py `
  cli\embedded-tools\validate_tensorrt_engines.py `
  cli\embedded-tools\TensorRTHandler.py
```

无 NVIDIA 环境时，可以完成构建、协议和隔离测试，但必须在发布记录中明确“未完成真实 TensorRT 构建验证”，不能把静态通过写成 GPU 验收通过。

### 3.2 本地版本和产物检查

```powershell
& .\videoenhancer.exe --version
& .\videoenhancer.exe --list-download-models --json > $env:TEMP\videoenhancer-models.json
```

确认：

- [ ] `--version` 与本次发布版本一致。
- [ ] 模型清单中最多只有一个 `Plugin/videoenhancer.exe` 路径。
- [ ] 预置 TensorRT Engine 不会被新客户端当作必需发布资源。
- [ ] 模型清单没有 `PotPlayer.7z`。

## 4. 生成本体发布包

先只构建、不上传，确认本地包无误：

```powershell
& .\release\build-modelscope-release.ps1 `
  -Version '1.0.6' `
  -UpstreamBase '1.4.2' `
  -HostBin 'C:\path\to\FFmpegFreeUI.6.1.39.extracted' `
  -Notes '填写面向用户的简短变更说明。'
```

脚本生成：

```text
release/dist/modelscope/stable.json
release/dist/modelscope/releases/<version>/VideoEnhancer-<version>-win-x64.zip
release/dist/package/<version>/package.json
```

检查清单和压缩包：

```powershell
$version = '1.0.6'
$zip = "release\dist\modelscope\releases\$version\VideoEnhancer-$version-win-x64.zip"
Get-FileHash -Algorithm SHA256 $zip
Get-Content -Raw -Encoding UTF8 release\dist\modelscope\stable.json
Expand-Archive -LiteralPath $zip -DestinationPath "$env:TEMP\VideoEnhancer-$version-check" -Force
Get-ChildItem "$env:TEMP\VideoEnhancer-$version-check"
```

- [ ] `stable.json.version`、`package.json.version` 和 CLI 版本一致。
- [ ] `stable.json.package.path` 指向当前版本目录，不指向旧版本。
- [ ] `stable.json.package.size/sha256` 与 ZIP 实际大小/哈希一致。
- [ ] `package.json.files` 只有 EXE、DLL、布局 JSON，逐文件大小和 SHA-256 正确。
- [ ] ZIP 内没有额外路径、目录穿越路径或模型文件。

## 5. 更新器隔离测试

必须在上传前运行：

```powershell
& .\release\test-updater.ps1 -Version '1.0.6'
```

结果必须包含：

```text
PASS: success / traversal / tamper / rollback
```

该测试覆盖：

- 正常替换 EXE、DLL、布局 JSON。
- 拒绝路径穿越。
- 拒绝文件内容被篡改或哈希不匹配。
- 中途替换失败后的完整回滚。

## 6. 发布本体到双源

### 6.1 发布顺序

先 GitHub，后 ModelScope。原因是更新器的首选源是 GitHub；先发布 ModelScope 会让部分网络环境先看到只有兜底源的版本状态。

### 6.2 一键发布

确认门禁全部通过后执行：

```powershell
& .\release\build-modelscope-release.ps1 `
  -Version '1.0.6' `
  -UpstreamBase '1.4.2' `
  -HostBin 'C:\path\to\FFmpegFreeUI.6.1.39.extracted' `
  -Notes '填写面向用户的简短变更说明。' `
  -PublishGithub `
  -PublishModelScope
```

脚本会：

1. 重新构建插件和单文件 CLI。
2. 用 CLI `--version` 做版本一致性校验。
3. 生成 ZIP、`package.json` 和 `stable.json`。
4. 创建 GitHub `v<version>` Release，上传 ZIP 和 `stable.json`。
5. 使用 `--repo_type dataset` 将同一份目录上传到 `AerithDream/VideoEnhancer-Releases`。

如果脚本在 GitHub 成功、ModelScope 失败，不要重新生成不同内容的包；保留本次 `dist`，修复登录/网络问题后只重试 ModelScope 上传，并重新做远端核对。

## 7. 发布模型资源

模型资源必须单独准备上传目录，不要直接把整个仓库根目录交给 ModelScope CLI。

### 7.1 上传前清单

- [ ] 目标仓库为 `AerithDream/VideoEnhancer-Models`，类型明确为 `dataset`。
- [ ] 目录结构符合 CLI 允许的根目录：`Backend`、`BasicVSR++`、`Bin`、`FlashVSR`、`Frame-Interpolation`、`ONNX`、`Param-Bin`、`Plugin`、`RIFE`、`PTH`。
- [ ] `PotPlayer.7z` 不在上传目录。
- [ ] 同一模型只有一个当前推荐路径；旧兼容归档不因习惯自动继续同步。
- [ ] 每个大文件已记录大小和 SHA-256。
- [ ] 本体兜底文件 `Plugin/videoenhancer.exe` 如需保留，资源列表只出现一次；“下载全部”不会批量下载它。

### 7.2 上传命令

```powershell
modelscope upload `
  AerithDream/VideoEnhancer-Models `
  'D:\staging\VideoEnhancer-Models' `
  --repo_type dataset
```

涉及同路径文件替换、缓存异常或上次上传中断时：

- 先确认本地文件和目标路径，没有直接执行删除或同步清理。
- 必要时清理本地上传缓存后使用 `--no-cache` 重试。
- 不使用未审查的 `--sync` 或递归删除操作。

### 7.3 模型远端验收

```powershell
& .\videoenhancer.exe --list-download-models --json > $env:TEMP\remote-models.json
```

- [ ] 预期模型全部出现，分页读取没有漏项。
- [ ] 每个远端文件大小与本地记录一致。
- [ ] 随机下载至少一个新增模型，CLI 校验 SHA-256 通过。
- [ ] RIFE、NCNN、TensorRT 权重没有因目录兼容逻辑重复显示。
- [ ] `Plugin/videoenhancer.exe` 若存在，路径唯一且不混入模型解压目录。

## 8. 双源交叉核验

发布后必须核对同一版本的版本号、路径、大小和哈希：

```powershell
$version = '1.0.6'
$gh = Invoke-RestMethod `
  -Uri 'https://api.github.com/repos/maxzrb/VideoEnhancer/releases/latest' `
  -Headers @{ Accept = 'application/vnd.github+json'; 'User-Agent' = "VideoEnhancer/$version" }
$ghStable = Invoke-RestMethod `
  -Uri (($gh.assets | Where-Object { $_.name -eq 'stable.json' }).browser_download_url) `
  -Headers @{ 'User-Agent' = "VideoEnhancer/$version" }
$msStable = Invoke-RestMethod `
  -Uri 'https://www.modelscope.cn/datasets/AerithDream/VideoEnhancer-Releases/resolve/master/stable.json'
```

必须满足：

- [ ] GitHub latest tag 为 `v<version>`。
- [ ] GitHub `stable.json.version` 等于 `<version>`。
- [ ] ModelScope `stable.json.version` 等于 `<version>`。
- [ ] 两份清单的 `package.path`、`package.size`、`package.sha256` 完全一致。
- [ ] GitHub ZIP 下载地址和 ModelScope resolve 地址均返回 HTTP 200/有效重定向。
- [ ] ModelScope 数据集 README 没有写反下载优先级。
- [ ] GitHub Release 资产只有 `stable.json` 和本体 ZIP，不含模型大包。

网络受限环境还应手动验证一次：让 GitHub 请求失败，确认插件能读取 ModelScope 清单并下载同一 ZIP。不能只验证“两个 URL 都能访问”，因为那不能证明兜底分支真的被执行。

## 9. 发布失败和回滚

### 9.1 本体发布失败

- 构建失败：修复源码后重新构建，不上传半成品。
- ZIP/清单哈希不一致：丢弃本地生成目录，重新生成，不手工编辑哈希。
- GitHub 已发布但包有问题：不要覆盖既有 Release 资产，递增补丁版本发布修正版。
- ModelScope 上传失败：保留同一份 `dist`，修复认证/网络后重试；不要重新打包出不同哈希。
- 双源版本不一致：暂停公告和自动更新，先恢复 ModelScope `stable.json` 与 GitHub 资产一致。

### 9.2 模型资源失败

- 单个模型损坏：先停止推荐该资源，再上传修正版并更新哈希记录。
- 远端出现重复路径或旧归档：新客户端先过滤；远端删除前必须明确列出路径、大小和影响范围。
- 发现授权或来源问题：停止继续分发该文件，记录风险和处理决定；不得用项目许可证替代第三方权重许可。

### 9.3 不要做的事

- 不要 `git reset --hard` 或用强制 checkout 清理工作树。
- 不要把令牌写进 PowerShell 历史以外的仓库文件、脚本或日志。
- 不要直接覆盖已公开版本的 ZIP、`stable.json` 或 GitHub Release。
- 不要在未退出 3FUI 时强行替换正在加载的 DLL。

## 10. 发布后收尾

- [ ] 将版本、变更、命令、双源 URL、哈希和测试结果写入 `docs/codex/STATUS.md`。
- [ ] 在 `version/工作进度.md` 增加中文用户向记录。
- [ ] 版本变化时更新 `version/版本迭代记录.md`，保留历史版本段。
- [ ] 记录本机是否有 NVIDIA、是否完成真实 TensorRT 验证。
- [ ] 记录 Git 分支、未提交文件和是否建议提交。
- [ ] 发布后再进行 3FUI 实机升级测试，确认 EXE、DLL、布局 JSON 三个文件均更新。
- [ ] 测试完成后提交源码和记录；不要把 `release/dist` 临时产物误提交。

### 10.1 默认提交与推送

本项目发布完成后，默认执行源码提交和推送，不把“只在本地发布”作为正常结束状态：

```powershell
git status --short --branch
git add README.md VideoEnhancerPlugin cli release docs/codex version
git commit -m "release: <version>"
git push fork HEAD:main
git status --short --branch
git log -1 --oneline --decorate
```

- [ ] 推送目标已确认是独立维护仓库 `fork`，不是 `origin` 上游仓库。
- [ ] 提交内容不包含令牌、用户配置、模型缓存、临时上传缓存或未审查的大型产物。
- [ ] 推送后远端分支和本地提交一致，工作树干净或剩余改动已有明确记录。
- [ ] 如果 GitHub Release 已创建但源码推送失败，必须先修复 Git 状态再宣布发布完成。
